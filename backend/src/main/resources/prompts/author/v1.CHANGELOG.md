# author/v1

2026-09-20. The first version, written from Document 4, Prompt 1: Author.

**Text**: the prompt of the document, placeholder for placeholder: the DSL cheat sheet, the few-shot example of
`v1.examples.json` (the three-paragraph card policy and its whole rule set), the policy in its own data section,
the analyst's hints, and the eight numbered instructions.

**Measured** (2026-09-20): ten live runs of the lending policy on `gpt-5.6-terra`, all ten schema-valid on the
first try, 67 to 101 seconds each, recorded in `fixtures/eval/recordings/openai/author/v1/`. Gate G1 asks for
nine of ten. Each draft had 17 to 24 rules over 12 to 15 fields.

**Two provider facts found on day 7**, both now in Document 4 rather than in this prompt:

- The strong model of the current lineup accepts only its own temperature, so none is sent.
- Structured output runs with strict mode **off**. Strict mode makes every declared property mandatory, and the
  DSL forbids some of them in context — a derived field has no `default` — so the model had to write a value the
  validator then refused, and every first-try document failed on exactly that. With the schema sent but not
  enforced, the same prompt answers a document the validator accepts.

**2026-09-20, later the same day**: the output cap went from 8,000 to 24,000 tokens, Document 4 first. On this
lineup the cap counts the model's reasoning tokens as well as the document it returns. A twelve-paragraph policy
measured 2,184 reasoning and 6,379 document tokens; a run that reasoned harder spent all 8,000 on reasoning,
returned `finish_reason: length` with no text at all, and the repair loop then answered an empty document with a
three-rule one that validated with warnings and looked like a result. The prompt text did not change.
