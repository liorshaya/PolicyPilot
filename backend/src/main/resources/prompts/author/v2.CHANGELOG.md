# author/v2

2026-09-27 (plan date; recorded 2026-09-24). The second version, the owner's decision on day 11 after evaluation run 1
scored `author/v1` at 0.12 rule recall and 0.00 case agreement; where the field names come from decided on day 15.

**Why**: the rules `author/v1` missed read field names the model had invented, such as `loan_amount` and
`employment_status`, which the labeled rule sets and their cases do not have, so most rules could not match and no
labeled case could even be decided. The names reach the model through the input the prompt already has, the
analyst's hints (Document 4, Prompt 1: Author, Field hints).

**Text**: `author/v1`, with one sentence added to instruction 1, word for word from Document 4: "When `<hints>` lists
the inputs the application supplies, use exactly those names, types, units and enum values for them, and declare an
input the list lacks only when the text cannot be decided without it." The system prompt, the example and the
settings are `author/v1`'s. `author/v1` stays in the registry, so `policypilot.ai.prompt-versions.author` compares the
two without a code change.

**Measured** (2026-09-24, `LiveAuthorPassIT`, OpenAI `gpt-5.6-terra`): the 18 labeled policies, each once with its
field hints, and the lending policy once more without hints (the render the tests replay): 19 of 19 schema-valid on
the first try. 167,588 tokens (82,012 in, 85,576 out) of the 360,000 the owner set: about 4,300 input tokens a call,
a third of the 12,000 Document 4's cost envelope gives.
