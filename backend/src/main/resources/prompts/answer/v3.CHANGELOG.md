# answer/v3

2026-09-28 (plan date; recorded 2026-09-25). The third version, the owner's decision on day 16, after the Definition of
Done walk found the chat step failing on the `ollama` profile.

**Why**: the conduct's first rule asked every prompt for "exactly one JSON object that conforms to the schema provided
by the API, and nothing else", with a parenthesis sending the chat to plain text. OpenAI's model followed the
parenthesis; qwen3:14b followed the first sentence. In evaluation run 2 and in the day 16 Ollama run it wrapped its
answers in a JSON object (Q-01 and Q-02 came back as `{"error": "<the not-covered sentence>"}`) and made no tool call,
so the chat step on the local model answered one question of four as labeled. Sent Q-01 with the text rule alone, it
called `getDecision` on both runs (a probe against the local Ollama, 2026-09-25). OpenAI had wrapped one answer of run 2
too: Q-30 came back as `{"answer": "..."}`, which is not the fixed sentence the refusal metric looks for.

**Text**: `answer/v2`'s user prompt, word for word. The system prompt takes `{textConduct}`, the conduct skeleton whose
first rule is `Respond in plain text following the citation protocol.` alone (Document 4, Shared Conventions, The output
rule). Every other prompt, and `answer/v1` and `answer/v2`, render byte for byte what they rendered before: the registry
test compares each version the recordings hold with the system text its recordings were sent with. `answer/v2` stays in
the registry, so `policypilot.ai.prompt-versions.answer` compares the versions without a code change.

**Settings**: `answer/v2`'s. On the `ollama` profile two settings changed with this version, both for the local model
alone: the retrieval threshold for bge-m3 is 0.58, and the answer thinks (Document 4, The threshold per embedding model
and Thinking on the local model). Without thinking, qwen3:14b still worked Q-02's what-if out of rule R-330 on each of
three runs of `answer/v3`; with it, it called `getDecision` first on each of three.

**Measured** (2026-09-25, `LiveAnswerPassIT`, the 30 labeled questions once each): on OpenAI 25 reached the model,
61,661 tokens in all, and the pass's answers to the three scripted questions are the ones the offline tests replay; on
Ollama 25 reached the model, in 654 s. The report is `docs/eval/2026-09-25-authorv2-reviewv1-answerv3-changev2.md`.

On OpenAI, Q-30 is now refused with the fixed sentence; Q-14 stays refused, by the retrieval threshold before any call.
On Ollama, no answer is wrapped in JSON, Q-01 calls `getDecision`, and Q-02 calls `getDecision` and then `simulate`. Its
refused covered questions are Q-08 and Q-14, which the new threshold stops at 0.471, and Q-28 and Q-29, which the model
refused; the threshold also takes Q-14's expected chunks out of retrieval recall, 22 of 23 where run 2 had 23. The Ollama
column moved with three changes at once, this version and the two settings above, and the deltas are theirs together.
Three of the local model's answers carry a word in another script, Arabic or Chinese, Q-02's among them: a habit of
qwen3 in Hebrew that no text of this version addresses. As in every pass, each question was asked once, and the answers
are kept as recorded. One pass is one sample: streamed as the adapter sends them, Q-01 and Q-02 began with a tool call
on 3 of 6 runs (6 of 8 at Qwen's recommended temperature for thinking, 0.6, which this version does not set), and one
walk of the demo through the interface called none. The chat step on the local model now works on some runs, not on
every one.
