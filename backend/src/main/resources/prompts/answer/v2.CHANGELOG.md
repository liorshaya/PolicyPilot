# answer/v2

2026-09-27 (plan date; recorded 2026-09-24). The second version, argued for by evaluation run 1 (2026-09-23) and held
until evaluation run 2 on day 15.

**Why**: run 1 refused a covered question, Q-08 ("how many applications were referred"), with the not-covered
sentence: the retrieved passages do not hold a count, and `answer/v1` did not say that a count is a tool's to give.

**Text**: `answer/v1`, with one sentence added to instruction 2: a question about how many decisions had an outcome,
which outcome or deciding rule is most common, or a share, is answered from `getDecisionStats`; a question about which
rules or conditions do something is answered from `listRules` when the context holds few rules; such a question is
never not covered. The system prompt's other rules and the settings are `answer/v1`'s. `answer/v1` stays in the
registry, so `policypilot.ai.prompt-versions.answer` compares the two without a code change.

**Measured** (2026-09-24, `LiveAnswerPassIT` and `LiveAnswerRecordingIT`, OpenAI `gpt-5.6-terra`): the 30 labeled
questions once each, then the three scripted demo questions in the demo's order: 25 of the 30 reached the model (the
Threshold stops Q-04, Q-14, Q-15, Q-22 and Q-26 before any call), 62,526 tokens in all.

The scripted questions were then recorded twice more (the owner's approval, 2026-09-24, about 40,000 tokens): the
pass's answer to Q-02 worded the simulated approval "אישור" where its label asks for "מאושר", and an answer that misses
its label is neither kept by the response cache nor replayed by the tests, so step 3 would have called the model on
every run. The first rerun worded it the same way; the second says "מאושרת", and its recording replaces the pass's.
Q-01 came back reworded with the same citations, still meeting its label, and Q-03 as it was. The same thing
happened to `answer/v1` on day 9.
