**When a gate fails**: the missing item gets the next morning, at most half a day, taken from the same phase's lowest item in the Scope ladder, never from another phase's days and never from days 17 to 19. A gate is never "mostly passed": either the proof exists or the item is on the cut list.

**Never cut**: the engine with its conformance suite and mutation gate, the validator, the security front door, decision persistence, the cloud deployment, the recorded-model tests, and days 17 to 19. **When ahead of plan**, the ladder runs backwards from rung 2: the encore first, then the Ollama column, then FR-20, then the remaining labeled policies; query rewriting for retrieval stays out unless recall at 8 misses its target on the Hebrew questions (Document 4).

## Daily routine and tracking

Every day from 2 to 16 has the same shape, and the shape is what makes the 40% test share real: the test list exists before the code, and the day is not over until it is green.

1. **First fifteen minutes**: read yesterday's worklog line; its slipped items come first, before anything new.
2. **List the tests**: turn the day's specification rows (conformance cases, validator codes, API routes, security controls, prompt contracts, requirement ids) into named, empty, failing tests in the right class (Document 6, Working Method). That list is the day's scope; what is not on it is tomorrow's.
3. **Fixtures before code** wherever the day table names a fixture; expected values come from the reference implementation, the OpenAPI document, the recordings or the labeled set, never from running the code.
4. **Red, green, refactor** per test. Drafts from Claude Code or Cursor are allowed for tests and code alike, and each generated test is interrogated before it is kept: it asserts a value from outside the code, it would fail if the behavior were wrong, it does not mock the thing under test.
5. **Merge only green**: a pull request merges to `main` with stages 1 to 6 green (stage 7 when `frontend/` or the API contract changed); `main` deploys itself. A red pipeline is fixed before any new test is written.
6. **The last hour**: the Definition of Done checklist for the day's tasks, the demo-step check on the cloud site for the step this phase enables, and the worklog line.
7. **Then stop.** There is no evening catch-up; slipped is slipped, and the gate decides.

**Tracking** lives in one file, `docs/worklog.md`: one line per day (date, day number, done, slipped, decisions taken, and the numbers copied from the CI job summary: line coverage per package, PIT score, batch time, first-token time), the gate proofs with their links, and the rehearsal fix lists on days 17 to 19. The evaluation report's metrics are copied in after days 11 and 15. A number that moves the wrong way for two days becomes a task; a requirement that slips twice goes to the Scope ladder discussion at the next gate.

**Changes to other documents**: the Brief's phase table now lists the first deployment under Phase 0, since this plan deploys the skeleton on day 1 and keeps `main` live from then on; Phase 4 keeps the final deployment checks. No other document changes: every route, threshold, test name and fixture path in this plan is taken from Documents 2 to 6 as they stand.
